# Windows 原生语音键入（Win + H）测试

此功能独立于豆包、微信输入法和 Vokie。遥控器 BLE / ATVV 解码后，仍通过
SayAll -> VB-CABLE 播放端 -> CABLE Output 录音端把声音送入 Windows；
新增的是语音键控制入口，**不是新的识别引擎**。

## 准备

1. Windows 10 / 11 可用的语音键入（需要网络、系统麦克风权限和可编辑文本框）。
2. SayAll 的语音设备选择 `CABLE Input` 或 `CABLE In 16ch`。
3. Windows `系统 → 声音 → 输入` 以及 Win+H 面板「选择默认麦克风」
   都设成 `CABLE Output (VB-Audio Virtual Cable)`。
4. 先在记事本内用键盘 Win+H 手动验证中文识别；测试之前关闭手动打开的听写面板，
   避免已有会话与自动开关冲突。

## 设置

连接页面选择「Windows 自带语音输入」。系统将保存
`voice_input_tool=windows_typing` 并清空旧「按住说话快捷键」，
原来的「其他工具」快捷键记忆仍然保留。无需打开「全按键支持」或安装第三方输入法。

## RC001 / RC003 真机验收（需分别记录）

- **启动**：记事本有文本焦点；按住遥控器语音键，观察 Win+H 面板出现并进入聆听；
  输入内容应来自 CABLE Output，而不是物理麦克风。
- **启动预热**：按下语音键后，SayAll 先向 CABLE 播放约 900ms 静音，
  再输出缓冲的真实语音。立刻说话的开头不得被 Windows 面板启动耗时吃掉。
- **识别收尾**：松开语音键后，SayAll 在真实语音后向 CABLE 输出约 1800ms 静音，
  让 Windows 检测句尾并提交结果，然后才尝试再次发送 Win+H 停止。
  检查文字是否出现、末尾有没有丢字。不要把“音频已经排空”当成“云端已经识别完成”。
  如果仍在聆听，请点击 Windows 面板麦克风暂停。
- **二次按住**：上次已暂停时再次按住应重新开始听写；应无意外 Win 键粘连。
- **快速点按、长按、连续多轮**：不应多次启动 / 关闭；记录 `windows_typing`
  的 start/preroll/postroll/stop 日志以及实际 Windows 面板状态。
  建议至少测试（a）按下立刻说一句 2 秒中文，（b）按下后等 1 秒再说，
  （c）连续说 8 秒，（d）只有 0.5 秒语音；
  识别失败时同时对照手动 Win+H 录入以及“窗口已聆听但尚未识别”的状态。
- **异常**：连接中断、休眠、退出、重新配置等路径会尝试清理本应用启动的听写，
  不应留下键盘按下状态。重连后应可正常输入。
- **兼容**：返回豆包、微信、Vokie / 其他工具，原来快捷键和语音路径应正常；
  方向键鼠标映射不受影响。

## 停止功能的已知限制

微软官方承诺的 Windows 语音键入启动方式是 **Win+H**；官方支持的停止方式
是点击语音面板上的麦克风按钮或说「停止聆听」等语音命令。
再发一次 Win+H 来暂停是依据现有 Windows 行为的**实验性兼容策略**，
**不是**微软公开的专用停止 API，也不保证每个 Windows 版本或已存在
手动启动的听写会话都遵守同一状态机。

本实现只记录「按键已提交」而不冒充「Windows 已停止」。
禁止向前台应用盲发 Escape、输入文字「停止聆听」或定位屏幕坐标点击，
以免干扰用户正在编辑的内容。必要时用户手动点击系统麦克风。
若真机发现 Win+H 不具备稳定的停止能力，下一步应基于 Windows UI Automation
识别并调用系统听写面板的麦克风控件，明确验证不同 Windows 版本的控件结构。

  新增静音前/后缓冲用于验证启动晚和停得早的问题，目前尚未在真机复测。
- **Windows 真机自动启停及文字识别：deferred（待 RC001 / RC003 实机验证）**。
